I want you to perform a COMPLETE FRONTEND UI/UX AUDIT and IMPROVEMENT of the DMHC CNC application.

Your goal is to make the frontend feel like a professional, production-grade CNC control application.

IMPORTANT:
This is a CNC machine-control application. UI/UX improvements must NEVER weaken safety or hide important machine state.

==================================================
1. GENERAL RULES
==================================================

- Focus on the frontend/UI/UX.
- Preserve all existing functionality.
- Do not remove existing features.
- Do not redesign the Machine Agent architecture.
- Do not modify backend behavior unless a frontend bug requires a compatible API correction.
- Do not change CNC safety rules.
- Do not remove confirmations from motion-capable actions.
- Do not make dangerous actions easier to trigger accidentally.
- Do not introduce automatic machine motion.
- Do not introduce automatic controller connections.
- Do not hide errors.
- Do not hide machine state.
- Do not replace real machine data with fake/demo data.
- Do not break Head 1 while improving Head 2.
- Head 1 and Head 2 must remain completely independent.

Before changing anything, inspect the existing frontend architecture and understand the current component structure.

==================================================
2. DESIGN GOAL
==================================================

Build a professional CNC control dashboard.

The UI should feel:

- Professional
- Technical
- Industrial
- Clean
- Modern
- Fast
- Responsive
- Easy to understand
- Safe
- Information-dense without becoming cluttered

It should look like software designed specifically for CNC operators, not a generic CRUD dashboard.

Prioritize clarity and operational usability over decorative design.

==================================================
3. UI/UX PRINCIPLES
==================================================

Apply proper UI/UX principles throughout the application:

- Clear visual hierarchy
- Consistent spacing
- Consistent typography
- Consistent button styles
- Consistent iconography
- Clear grouping of related controls
- Strong distinction between machine state and user actions
- Clear disabled/loading states
- Clear success/error states
- Prevent accidental destructive actions
- Keep important information visible
- Avoid unnecessary dialogs
- Avoid excessive animations
- Use animation only when it communicates state
- Maintain good keyboard accessibility
- Maintain good contrast
- Maintain readable text
- Avoid tiny controls
- Avoid ambiguous icons
- Use tooltips where appropriate
- Keep frequently used CNC controls easy to reach

Do not create visual clutter.

==================================================
4. MACHINE CONTROLLER PAGE
==================================================

The Machine Controller page is the most important part of the application.

Redesign its layout professionally while preserving functionality.

The operator should immediately understand:

1. Which heads exist
2. Which head is connected
3. Which COM port is assigned
4. Current machine state
5. Current X/Y/Z position
6. Alarm state
7. Connection state
8. Current operation
9. Feed rate
10. Jog controls
11. Machine controls
12. Console output

The most important machine state should be visible without navigating through multiple screens.

==================================================
5. HEAD 1 AND HEAD 2
==================================================

Create a clear visual separation between Head 1 and Head 2.

Both heads should have equivalent UI capabilities.

Each head should have its own:

- Connection controls
- COM port selector
- Connection status
- Machine state
- DRO
- X/Y/Z positions
- Alarm indicator
- Jog controls
- Feed rate
- Home
- Reset
- Unlock
- Work zero
- Work offset
- GRBL settings
- Streaming controls
- Console

Do not make Head 2 feel like an afterthought.

Head 1 and Head 2 should look like two professional independent CNC controller panels.

==================================================
6. CONNECTION UX
==================================================

Make connection state extremely clear.

Use clear states such as:

DISCONNECTED
CONNECTING
CONNECTED
ERROR

Show the selected COM port clearly.

When connecting:

- Disable conflicting controls while connection is pending.
- Show a visible loading state.
- Do not allow duplicate connection requests.
- Show errors clearly.

When connected:

- Make the connected state obvious.
- Enable appropriate machine controls.

When disconnected:

- Clearly disable controls that require a connection.

Do not silently fail.

==================================================

Make X/Y/Z coordinates highly readable.

Use a layout such as:

Y
000.000 mm

Z
000.000 mm

Make units clear.

Clearly distinguish:

- Machine coordinates
- Work coordinates

Avoid excessive decimal formatting that makes values difficult to read.

==================================================

Create a clear status indicator.

Examples:

DISCONNECTED

==================================================
10. CONSOLE SYSTEM
==================================================

There MUST be TWO persistent consoles.

One for Head 1.
One for Head 2.

Each console must:

- Always remain accessible
- Maintain its own history
- Never mix messages
- Show commands
- Show GRBL responses
- Show errors
- Show streaming information
- Show timestamps if supported
- Automatically scroll when appropriate
- Allow the operator to inspect older messages
- NOT disappear after sending a command
- NOT clear automatically

Provide a visible "Clear" button only if clearing is already supported.

Do not automatically clear console history after:

- Connect
- Disconnect
- Jog
- Home
- Reset
- Command
- Stream
- Pause
- Resume
- Stop
- Settings operations

The operator must be able to continuously monitor both controllers.

==================================================
13. MACHINE SAFETY UX
==================================================

Safety is more important than visual polish.

Preserve:

- Confirmation dialogs
- Explicit head selection
- Confirm:true requirements
- Existing motion safeguards
- One-port/one-head enforcement
- Local-only Machine Agent model

For dangerous actions:

- Home
- Jog
- Reset
- Unlock
- Console commands
- G-code streaming
- Stop

make the action intent obvious.

Do not use misleading button placement.

Do not place dangerous buttons directly next to commonly clicked harmless actions without sufficient distinction.

14. RESPONSIVE DESIGN
==================================================

The UI must work well on:

- Desktop
- Laptop
- Smaller laptop screens
- 1366x768
- 1440x900
- 1920x1080

Do not assume a huge monitor.

On smaller screens:

- Preserve important machine state
- Avoid horizontal overflow
- Stack panels intelligently
- Keep controls accessible
- Keep consoles usable

==================================================
15. ACCESSIBILITY
==================================================

Implement good accessibility:

- Keyboard navigation
- Visible focus states
- Proper button labels
- ARIA labels where necessary
- Good color contrast
- Do not communicate important state using color alone
- Disabled states must be understandable
- Inputs must have clear labels

==================================================
16. PERFORMANCE
==================================================

The frontend must remain fast.

Avoid unnecessary re-renders.

Pay special attention to:

- Live telemetry
- SSE events
- DRO updates
- Console messages
- Streaming progress

Do not cause the entire application to re-render every time telemetry arrives.

Use appropriate React state architecture and memoization where useful.

Do not introduce premature complexity.

==================================================
17. ERROR HANDLING
==================================================

Every important operation must provide useful feedback.

Bad:

"Something went wrong."

Good:

"Head 2 connection failed: COM5 could not be opened."

Show:

- What failed
- Which head
- What operation
- Useful error information
- Recovery action when possible

Do not expose confusing technical stack traces to normal operators.

==================================================
18. LOADING STATES
==================================================

Every asynchronous operation should have a clear loading state.

Examples:

Connecting...
Refreshing settings...
Sending command...
Homing...
Starting stream...
Stopping...
Disconnecting...

Prevent duplicate clicks while operations are pending.

Head 2 is disconnected.

No G-code loaded.
