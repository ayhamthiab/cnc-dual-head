# 4. CREATE A NEW LOCAL MACHINE AGENT

Create a new independent component called:

```text
machine-agent
```

The purpose of this component is:

```text
Frontend
   ↓
Machine Agent API
   ↓
UGS Core
   ↓
GRBL
   ↓
Serial
```

The Machine Agent must be designed to run **locally on the computer physically connected to the Arduino**.

This is critical.

A remote Replit/Cloud server cannot directly access:

```text
COM3
COM4
/dev/ttyUSB0
/dev/ttyACM0
```

on the user's local computer.

Therefore:

```text
Cloud/Web Application
        X
        │
        X
    USB Serial
```

is NOT acceptable.

The Local Machine Agent must run on the machine that has physical access to the Arduino.

# 8. CONTROLLER REGISTRY

The system must support at least two independent GRBL controllers.

Example:

```text
Controller 1
    ↓
Arduino #1
    ↓
Head 1

Controller 2
    ↓
Arduino #2
    ↓
Head 2
```

Each controller must have an independent:

* UGS controller instance
* Serial connection
* state
* status
* position
* error state
* connection state

Conceptually:

```text
head-1
    └── GrblController
         └── Serial Port #1

head-2
    └── GrblController
         └── Serial Port #2
```

Do NOT allow both controller sessions to use the same serial port.

# 9. SERIAL PORT DISCOVERY

Implement:

```http
GET /v1/ports
```

The response should provide enough information for the frontend to display available serial devices.

For example:

```json
[
  {
    "address": "COM3",
    "description": "USB Serial Device",
    "manufacturer": "Arduino"
  }
]
```

The exact fields should follow what UGS/JSerialComm actually provides.

Do not fabricate manufacturer information.

---

# 10. CONNECT

Implement:

```http
POST /v1/controllers/{controllerId}/connect
```

Example request:

```json
{
  "port": "COM3",
  "baudRate": 115200
}
```

The agent should:

1. Validate the controller ID.
2. Validate the port.
3. Ensure the port is not already used by another controller.
4. Create/initialize the UGS GRBL controller.
5. Open the serial connection.
6. Detect/receive the GRBL startup information if available.
7. Start status monitoring using UGS functionality.
8. Return the connection state.

Example response:

```json
{
  "controllerId": "head-1",
  "connection": "connected"
}
```

Do NOT execute:

```text
$H
G0 ...
G1 ...
```

or any movement command during connection.

---

# 11. DISCONNECT

Implement:

```http
POST /v1/controllers/{controllerId}/disconnect
```

It must:

1. Stop status monitoring if necessary.
2. Close the UGS communication layer cleanly.
3. Close the serial port.
4. Update controller state.
5. Notify the frontend.

Disconnecting must NOT send a movement command.
