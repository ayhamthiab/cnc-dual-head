B. Work Position (WPos) 
The coordinate system used by the operator/program.

WPos = X10 Y20 Z0

There is still a serious command formatting bug in the Machine Agent.

The Set Work Offset command currently reaches the GRBL simulator as:

10 P0 L20 X??Y??Z??

This is invalid GRBL syntax and causes:

error:2

The command MUST be generated exactly in valid GRBL format.

For example:

G10 P0 L20 X0 Y0 Z0

or when only X is selected:

G10 P0 L20 X0

or:

G10 P0 L20 Y0

or:

G10 P0 L20 Z0

Do NOT send:
10 P0 L20...
Do NOT send:
X??Y??Z??
Do NOT use placeholders, question marks, or corrupted/missing characters.

Investigate the actual backend command-construction code. Do not only change the frontend.

Add a single centralized command builder, for example:

buildSetWorkOffsetCommand(x, y, z)

It must:
- Start with exactly `G10`
- Include `P0`
- Include `L20`
- Append only axes that were actually provided
- Format numeric values correctly
- Separate parameters with spaces
- End with `\n`

Examples:

Input:
X=0, Y=0, Z=0

Output:
G10 P0 L20 X0 Y0 Z0\n

Input:
X=0, Y=null, Z=null

Output:
G10 P0 L20 X0\n

Input:
X=10.5, Y=-20, Z=0

Output:
G10 P0 L20 X10.5 Y-20 Z0\n

Also investigate why characters are being transformed into `??` and why `G` is missing from `G10`.

This indicates the problem may be occurring in the request parsing, string construction, encoding, or command sanitization layer.
