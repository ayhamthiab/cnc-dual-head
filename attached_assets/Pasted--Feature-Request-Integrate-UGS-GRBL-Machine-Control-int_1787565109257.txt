# 2. New Required Feature

I want to add a **Machine Control / GRBL Control** feature to this application.

The goal is to make the application capable of controlling an Arduino running GRBL through a serial connection.

However, I do NOT want to build a complete CNC controller from scratch.

Instead, I want to reuse the existing **Universal Gcode Sender (UGS)** open-source implementation/APIs/components wherever technically possible.

The key idea is:

```text
My Existing Application
        │
        ├── G-code generation
        ├── G-code processing
        ├── Head 1 / Head 2 / Gap Fill
        └── Machine Control UI
                 │
                 ▼
        UGS / UGS-compatible
        control implementation
                 │
                 ▼
             Serial
                 │
                 ▼
        Arduino + GRBL
                 │
                 ▼
             CNC Machine
```

# 3. Main Requirement

I want my software to be able to perform the same type of machine-control operations that UGS performs.

The application should ideally be able to:

### Serial Connection

* Detect/select serial port
* Select baud rate
* Connect to Arduino/GRBL
* Disconnect
* Detect connection state
* Handle connection errors

### G-code Streaming

The application should be able to send the generated G-code directly to GRBL.

For example:

```text
Generated Head 1 G-code
        │
        ▼
Machine Control
        │
        ▼
Serial
        │
        ▼
Arduino + GRBL
```

The user should not have to manually download the G-code and then open UGS separately.

# 4. Machine Commands

The application should support GRBL commands such as:

```text
$H
```

for homing.

It should also be possible to send other GRBL/system commands and manual G-code commands.

Examples:

```text
$H
$$
$#
$G
$I
?
G0 X0 Y0
G1 X100 Y100 F1000
```

The exact supported command set should be determined from the UGS/GRBL implementation and GRBL protocol.

Do not assume unsupported commands.

# 7. Run / Pause / Resume / Stop

The application should support:

### Run

Start streaming a G-code file to GRBL.

### Pause / Hold

Pause the machine using the appropriate GRBL/UGS mechanism.

### Resume

Continue execution.

### Stop / Abort

Safely stop the current operation according to GRBL/UGS behavior.

The implementation must follow the established GRBL protocol rather than inventing a new protocol.

# 14. Multi-Head Consideration

This project uses two physical heads.

Therefore, investigate an important architectural question:

Can the UGS-based control layer manage:

```text
Arduino/GRBL #1 → Head 1
Arduino/GRBL #2 → Head 2
```

as two independent serial controllers?

Potentially:

```text
                    Node.js
                       │
             ┌─────────┴─────────┐
             ▼                   ▼
       UGS Controller 1     UGS Controller 2
             │                   │
          Serial 1            Serial 2
             │                   │
        Arduino #1          Arduino #2
          GRBL                 GRBL
             │                   │
          Head 1              Head 2
```

Determine whether UGS can support this architecture programmatically.

Also determine whether both controllers can operate simultaneously.

This is important because the existing project intentionally generates Head 1 and Head 2 as separate G-code outputs and is designed around parallel operation.

# 16. Safety Requirements

The machine-control feature must be designed carefully.

The application must never silently send unexpected motion commands.

The architecture should provide:

* Clear connection state
* Clear machine state
* Emergency stop/abort handling where supported
* Confirmation where appropriate
* Error reporting
* GRBL alarm reporting
* Streaming state
* Prevention of accidental duplicate streaming
* Proper serial disconnect handling
* No automatic motion unless explicitly requested
* No automatic homing unless explicitly requested

Do not implement safety-critical behavior differently from the established UGS/GRBL behavior without a strong reason.
